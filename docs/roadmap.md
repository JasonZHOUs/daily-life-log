# Daily Life Log 改进清单（给 Claude Code）

> 项目：Daily Life Log（https://daily-life-log.vercel.app/）
> 目标：让这个日常记录 App 更完善、更好用，重点是坚持成本低、数据口径一致、手机上好用。
> 使用方法：按阶段顺序做，一次只做一个阶段，做完跑通测试再进入下一阶段。不要一次性重构整个 App，也不要在没有备份 / 迁移方案的情况下改数据结构。

## 通用原则

- [ ] 每次改动前先确认现有数据不会丢失，涉及数据结构变化时先写迁移方案
- [ ] 保持“已同步到账号”和“仅在本设备使用”两种模式的数据互不覆盖
- [ ] 所有时间都按用户本地时区（Asia/Singapore）显示和计算，不要直接用 UTC 日期判断“今天”
- [ ] 手机端优先测试：小屏、大按钮、单手可操作
- [ ] 每个阶段完成后都要能正常登录、正常查看当天记录、正常新增一条记录
- [ ] 登录失败时要给出可操作的提示，不要只显示一句笼统的错误

---

## Phase 0：基线与安全（先做，约 0.5 天）

- [ ] 梳理现有数据模型：饮食、补剂、计划任务、饮水、心情 / 精力 / 睡眠 / 步数、活动时长、睡前小结，分别存在哪里、字段是什么
- [ ] 确认现有账号同步逻辑：登录后同步什么、本地模式保存到哪里、两者切换时会发生什么
- [ ] 给关键数据加导出 / 备份入口（至少能导出当月 JSON 或 CSV），上线前先在测试账号上验证一次恢复流程
- [ ] 统一日期处理：当天、昨天、明天的边界按本地时区计算，跨午夜不再串天
- [ ] 补齐界面语言：默认全中文，EN 切换不要出现中英文混杂的半成品页面

**验收标准：** 老数据全部可读；新旧两种模式切换后数据不丢失；当天记录在午夜前后不串天。

## Phase 1（P0）：任务与记录联动 —— 解决“明明做了却显示没做”

背景：2026-10-29 的记录里，早餐和早上补剂已有饮食 / 补剂记录，但计划页对应任务仍未勾选。

- [ ] 定义统一的完成口径：计划任务的完成状态以勾选框为准，饮食 / 补剂记录作为完成证据，而不是两套独立状态
- [ ] 饮食记录联动：记录了早餐（含蛋白质）后，自动勾选当天“早餐”计划任务；删除该饮食记录时，相应任务恢复未完成（并给出提示）
- [ ] 补剂记录联动：标记补剂已服用后，自动勾选对应的补剂任务；早上 / 晚上分开统计，不要混在一起
- [ ] 手动勾选也联动：勾选任务时，如果还没有对应记录，弹出快速记录入口（而不是只打一个勾）
- [ ] 在计划页明确区分三类状态：已完成、已有记录但未勾选（需要提示用户确认）、未完成
- [ ] 修复历史数据口径：在当天页面上，已有记录但未勾选的任务要一眼看出来，不要悄悄改写历史

**验收标准：** 记早餐 → 早餐任务自动勾选；记补剂 → 补剂任务自动勾选；反向删除记录时状态同步回退；当天“已完成 / 未完成”只有一个口径。

## Phase 2（P0）：提醒 —— 让提醒走出 App

背景：现在“下一项”只在页面内高亮，关掉 App 就看不到。

- [ ] 下一项前 15 分钟提醒一次
- [ ] 到点未完成时再提醒一次，不要无限骚扰（每天同一任务最多提醒 2 次）
- [ ] 提醒内容要具体：任务名 + 时间 + 一句话该做什么，例如“15:30 下午加餐，16:00 上课”
- [ ] 晚上固定时间（建议 23:00 前）发一天小结：今天还剩什么、明天第一件事是什么
- [ ] 提醒设置页：可以开关每一类提醒（计划、补剂、饮水、睡前小结），不要只有全局开关
- [ ] PWA / 通知权限引导：如果浏览器不支持推送，要在页面内明确说明，并提供替代方案（例如打开 App 时的醒目横幅）

**验收标准：** 15:30 的下午加餐能在 15:15 左右收到提醒；过期未做有一次跟进提醒；用户可以在设置里关掉某一类提醒。

---

## Phase 3（P0）：快速录入与手机端体验

- [ ] 常用食物、补剂、任务做成模板 / 收藏，一键复用，不要每次重新输入克数和名称
- [ ] “最近使用”列表：最近 7 天用过的食物和补剂排在前面
- [ ] 饮水、补剂、心情、精力改成一键点选：饮水 +1 杯、补剂点一下即完成
- [ ] 新增记录的表单控制在 2 步以内完成，手机端按钮足够大，输入框不要被键盘遮挡
- [ ] 当天页面结构：顶部是“下一项”，其次是今日进度（热量、蛋白质、饮水、任务完成数），详情往下翻
- [ ] 支持 PWA 安装，离线能记，联网后自动同步，同步冲突时不要静默覆盖

**验收标准：** 记一杯水、记一次补剂、记一顿常用早餐都能在 10 秒内完成；离线记录联网后不丢失。

---

## Phase 4（P1）：趋势与周报 —— 从记账本变成能看出变化的工具

- [ ] 周视图 / 月视图：热量、蛋白质、体重、睡眠、心情、精力、步数的趋势图
- [ ] 目标进度条：热量、蛋白质、饮水（例如 8 杯）、任务完成数，一眼看到完成度
- [ ] 连续打卡统计：连续完成天数、中断后如何恢复计算，不要把补记算成连续
- [ ] 自动周报：本周哪几天达标、哪项最容易漏、和上周相比的变化
- [ ] 周报要可分享 / 可导出，不要只存在页面里

**验收标准：** 打开周视图能看到 7 天趋势；周报能说出本周最容易漏的 1–2 项。

---

## Phase 5（P1）：健康数据与计划模板

- [ ] 接入 Apple Health（或设备健康数据）：自动同步步数、睡眠、运动消耗，减少手动填写
- [ ] 活动计时：学习、实验、AI 项目、职业技能支持一键开始 / 结束计时，而不是事后估算分钟数
- [ ] 按星期几的计划模板：一键生成当天计划，例如实验日、上课日、健身日模板
- [ ] 模板支持拖动改时间、批量改重复任务
- [ ] 可选的日历同步：计划时间变化时提示冲突，不要静默覆盖日历

**验收标准：** 步数和睡眠不再需要手动填；按模板生成一天计划不超过 3 次点击。

---

## Phase 6（P1）：账号、同步与数据安全

背景：登录曾多次提示“Invalid login credentials”，用户很难判断是账号错、密码错还是根本没注册。

- [ ] 明确区分两种模式：“仅在本设备使用”（本地数据）与“登录同步”（账号数据），在登录页和设置页都写清楚
- [ ] 切换模式前提示数据去向，切换后不要把本地数据和账号数据互相覆盖
- [ ] 登录错误提示要具体：账号不存在 / 密码错误 / 网络问题，分别给下一步操作（注册、重置密码、重试）
- [ ] 补齐密码重置流程，并测试一次完整流程
- [ ] 导出 / 备份：按日期范围导出，支持 JSON 和 CSV，导出文件里包含饮食、补剂、任务、身心状态
- [ ] 删除账号 / 清空数据前二次确认，并说明哪些数据会被删、哪些本地数据会保留

**验收标准：** 新用户能分清两种模式；登录失败时知道下一步该点哪里；导出文件能完整恢复当月记录。

## Phase 7（P2）：智能建议与体验加分

- [ ] 根据剩余热量和蛋白质，推荐下一餐的大致搭配（只给建议，不自动记入）
- [ ] 睡前小结自动生成草稿：今天的一个收获、明天的 3 件事，用户改一下就能保存
- [ ] 深色模式、大字体等无障碍选项
- [ ] 搜索历史记录：按关键词、按日期范围搜饮食、任务、睡前小结
- [ ] 数据异常提醒：例如连续两天热量或蛋白质明显偏低、连续多天睡眠未填，提醒一次即可，不要天天弹

**验收标准：** 睡前小结有草稿可改；搜索能找到一周前的某条记录；异常提醒不骚扰。

## 补充：好用的小改进（用户 2026-10-30 已确认有用）

> 这一节是第一版清单之外的补充，只收用户觉得贴手的小改进，按“录入快、不容易错、按实际情况走”来排。不用等前面的大阶段做完，可以穿插着做。

### A. 计时与活动记录

- [ ] 学习、实验、AI 项目、职业技能支持一键开始 / 结束计时，支持暂停和备注“今天做了什么”，结束时自动记入当天活动时长，不要事后估算分钟数
- [ ] 计时进行中在当天页面顶部能看到，换页面、锁屏回来也不会丢

**验收标准：** 开始一次实验计时，结束后续时长自动出现在当天活动里；中途切走再回来计时还在。

### B. 手机小组件与快捷操作

- [ ] iOS 小组件：显示下一项、今天任务完成数、饮水杯数，一眼看到
- [ ] App 图标长按快捷入口：记一杯水、记一次补剂、开始一次计时
- [ ] 补剂、饮水支持手表一键记录，不用解锁手机

**验收标准：** 不打开 App 就能看到下一项；长按图标 2 步内完成一次记水或记补剂。

### C. 误删能恢复

- [ ] 删除饮食、补剂、任务、饮水记录后进 7 天回收站，7 天内能找回
- [ ] 修改克数、时间等字段时保留修改记录，能看到改之前是多少

**验收标准：** 误删一条记录后能在回收站找回；改过克数后能查到原值。

### D. 提醒按实际情况发

- [ ] 健身前晚饭提醒：只有当天还没记晚饭才发，已经记了就不再发
- [ ] 天热或练完之后，饮水提醒可以多一次；考试周的提醒合并成一条，不要一条条弹
- [ ] 提醒设置里能按类别开关，不要只有全局开关

**验收标准：** 已记晚饭的那天不再收到健身前晚饭提醒；考试周一天最多收到一条合并提醒。

### E. 周末与考试周模板

- [ ] 存几套计划模板：工作日、实验日、健身日、周末轻量版、考试周版
- [ ] 考试周模板自动把复习排进去，计划项比平时少，不用每天从头建 10 项任务
- [ ] 模板生成后只改当天不一样的一两项即可

**验收标准：** 选考试周模板生成一天计划不超过 3 次点击；周末模板的任务数明显少于工作日。

### F. 一键复制昨天的计划

- [ ] 点一下“复制昨天”，时间、任务都带过来，只改今天不一样的一两项
- [ ] 实验日、上课日各存一个常用版本，复制起来更快

**验收标准：** 复制昨天后生成当天计划不超过 3 次点击。

### G. 列表上直接完成

- [ ] 计划列表里左滑或长按就能勾选，不用点进详情页
- [ ] 饮水、补剂、心情、精力在列表上点一下即完成

**验收标准：** 在列表页完成一项任务不超过 1 次操作。

### H. 语音记录

- [ ] 睡前小结、刚吃完的食物支持按住语音输入，自动转成文字，用户改一下就能保存
- [ ] 语音转文字失败时保留原语音，提示用户重试或改打字

**验收标准：** 说一句话能生成一条可编辑的睡前小结草稿。

### I. 拍照先记一餐

- [ ] 吃饭时先拍张照就算记了一餐，照片和时间先存下来
- [ ] 晚上有空再打开照片补热量和克数，不补也不丢这条记录

**验收标准：** 拍一张照就能生成一条待补全的饮食记录；补全后热量和蛋白质正常计入当天。

### J. 一天结束“一键收尾”

- [ ] 晚上固定一个收尾页，三步确认：水喝够没、补剂吃完没、今天心情怎么样
- [ ] 点完自动生成睡前小结草稿，用户改一下就能保存

**验收标准：** 收尾页 3 步内完成，并生成一条睡前小结草稿。

### K. 没做的项第二天处理一次

- [ ] 早上打开时对昨天未完成的任务问一次：移到今天、直接跳过、还是删掉
- [ ] 选完后列表就干净了，未完成的任务不会一直留着

**验收标准：** 昨天未完成的任务在第二天早上只出现一次处理入口，选完后不再重复出现。

### L. 克数用加减步进

- [ ] 记食物克数时旁边放 +10g、-10g 按钮，数字键盘直接弹出来
- [ ] 常用克数（例如鸡蛋 100g、全麦面包 140g）点几下就能调好

**验收标准：** 记一次常用食物的克数不超过 3 次点击。

## 每个阶段都要跑的测试清单

- [ ] 登录 / 注册 / 密码重置 / 本地模式切换
- [ ] 当天新增、修改、删除一条饮食、补剂、任务、饮水记录
- [ ] 刷新页面、换设备登录后，数据一致
- [ ] 手机小屏下，当天页面不溢出、不遮挡、不需要横向滚动
- [ ] 午夜前后切换日期，记录不串天
- [ ] 构建通过，无新增的控制台报错

## 建议的实施顺序

1. Phase 0 → Phase 1 → Phase 2 → Phase 3（先把“记了算数、提醒得到、录入够快”做扎实）
2. Phase 4 → Phase 5（再做趋势和自动化）
3. Phase 6 穿插在 Phase 1–3 之间做登录提示和导出，不要拖到最后
4. Phase 7 最后做，属于加分项
